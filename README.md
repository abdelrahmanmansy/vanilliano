# فانيليانو — متجر خامات الحلويات

متجر إلكتروني لخامات الكيك والكاندي والتغليف، مبني بـ React + Vite + Tailwind،
مع لوحة تحكم لصاحب المتجر تعدّل المنتجات والأسعار والمخزون من الإنترنت مباشرة.

---

## 1) تشغيل المشروع محلياً

```bash
npm install
npm run dev
```

افتح `http://localhost:5173`.

- `صفحة المتجر`: `http://localhost:5173/`
- `لوحة التحكم (دخول صاحب المتجر)`: `http://localhost:5173/admin`

### المنتجات
المنتجات الافتراضية محفوظة في:
- `src/data/products.js` — منتجات المتجر الأصلية (صور SVG للعرض)
- `src/data/sweetart.js` — منتجات Sweet Art + دريم + خلطات الكيك (صور حقيقية)

---

## 2) تسليم المشروع لرب العمل (صاحب المتجر)

### الخطوة 1: إنشاء مشروع Supabase مجاني (مرة واحدة)
1. ادخل على https://supabase.com واعمل حساب/دخول بحساب Google أو GitHub.
2. اضغط **New project**، اختار اسم (مثلاً `vanilliano`)، وأقرب منطقة (تجاه `eu-central-1` أو `Frankfurt`).
3. خلي الرقم السري اللي هيطلبوه في مكان آمن (مرة واحدة فقط بيظهر).
4. افتح **SQL Editor** (من القائمة الجانبية) والصق محتوى ملف `supabase/schema.sql` واضغط **Run**. هذا ينشئ جدول `products` وقواعد الأمان، بحيث الزوار يقرؤوا بس، وصاحب المتجر هو اللي يكتب.

### الخطوة 2: ربط المتغيرات
1. في Supabase: **Settings → API**.
2. انسخ `Project URL` وحطه في `.env` كالتالي:

```env
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

3. كرر نفس القيمتين في أي خدمة توزيع (GitHub Pages/Netlify/Vercel) كـ *environment variables* بنفس الأسماء `VITE_...`.

### الخطوة 3: إنشاء حساب صاحب المتجر (مرة واحدة)
1. في Supabase: **Authentication → Users → Add user**.
2. اعمل مستخدم بالبريد وكلمة سر صاحب المتجر (مثال: `owner@vanilliano.com` + كلمة سر قوية).
3. مهم: في كود المصدر يوجد متغيّر `OWNER_EMAIL` داخل `src/context/AuthContext.jsx` —
   حطه نفس البريد اللي فوق، عشان النظام يتعرف إن صاحب المتجر هو المالك الحقيقي.

### الخطوة 4: تعبئة قاعدة البيانات بالمنتجات (مرة واحدة)
بعد ربط `.env` وشغل `npm run dev`:
1. افتح `http://localhost:5173/admin` وسجّل دخول بحساب صاحب المتجر.
2. انتقل إلى **لوحة التحكم → المنتجات**، اضغط زر **«تعبئة القاعدة بالمنتجات»** (يظهر فقط لصاحب المتجر).
3. في خلال ثوانٍ تتحرر كل منتجات المتجر (أكثر من 200 منتج) في قاعدة Supabase.

### الخطوة 5: التعديل اليومي من صاحب المتجر
- ادخل من `موقعك/admin` (أو من "دخول صاحب المتجر" في صفحة تسجيل الدخول).
- في تبويب **المنتجات**: ابحث، عدّل السعر، غيّر حالة المخزون (متوفر/نفذ/منخفض)، الصورة، الوصف… إلخ.
- أي تعديل ينشر فوراً لجميع زوار المتجر (لأنهم يقرؤون من نفس قاعدة البيانات).
- **انسخ زر المزامنة** فقط لو أردت إعادة تعبئة كل المنتجات بأسماء/أسعار الافتراضي مرة أخرى.

## 3) التوزيع (النشر) للجمهور

المشروع جاهز للنشر على أي خدمة ستاتيك (GitHub Pages / Netlify / Vercel).

- أمر البناء: `npm run build` (النتيجة في مجلد `dist/`).
- ملف GitHub Actions جاهز في `.github/workflows/deploy.yml` (يبنى من فرع `master`).
- عند النشر لا تنسَ تعبئة متغيرات البيئة `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`.

> ملاحظة خاصة بـ GitHub Pages: `base` في `vite.config.js` مضبوط على `/vanilliano/`.
> إن غيّرت اسم المستودع، غيّر `base` بنفس الاسم.

---

## 4) ملاحظات تقنية

- المحل متجه للعربية (RTL) ويستخدم خط Cairo.
- بيانات الطلبات/السلة/المفضلة محفوظة في المتصفح (`localStorage`) — لا تحتاج قاعدة بيانات لسلة الشراء التجريبية.
- عند إيقاف إعداد Supabase، المتجر يعمل بوضع تجريبي محلي كامل (التعديلات لا تظهر للآخرين).
